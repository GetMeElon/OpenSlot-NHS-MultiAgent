# **Strategic Architecture and Implementation Plan for the MongoDB Agentic Evolution Hackathon: Transparent NHS Appointment Delegation System**

The proposal to pivot the hackathon project from a standard rules-based outpatient slot recovery engine to an advanced, transparent, and multi-channel appointment delegation process represents a highly strategic and necessary evolution. The original build plan, as detailed in the provided documentation, outlined a system heavily reliant on static Python rules, synthetic data filtering, and a Streamlit administrative interface.1 While practically applicable to the National Health Service (NHS)—which recorded 146.1 million outpatient appointments and 8.1 million Did Not Attend (DNA) events in the 2024–2025 period 1—the original design fails to align with the core mandates of the MongoDB Agentic Evolution Hackathon. Crucially, the explicit rules of the hackathon ban Streamlit applications and basic Retrieval-Augmented Generation (RAG) projects.1 Furthermore, a strictly rules-based eligibility engine fundamentally lacks the autonomous decision-making, adaptive reasoning, and persistent memory required to be classified as an authentic agentic system.1

The proposed pivot introduces a dynamic, multi-agent architecture focused on the complete lifecycle of document making, queue management, and appointment delegation. By shifting the focus to a transparent delegation process—where an autonomous system identifies a cancelled slot, reaches out to patients via their preferred communication channels (voice, SMS, email), negotiates appointment times, dynamically informs patients of subsequent opportunities if they decline, and seamlessly transitions to the next patient in the queue—the project aligns perfectly with the cutting-edge requirements of the event. This approach directly addresses the hackathon's mandate to eliminate basic chat-bound tools and instead deploy artificial intelligence as an autonomous partner integrated into real-world operational workflows.2 Furthermore, by explicitly focusing on eliminating the "black box" of NHS scheduling, the project maximizes its performance against the "Impact Potential" judging criterion, ensuring patients feel cared for and administrators maintain complete oversight over algorithmic fairness.

This exhaustive report details the technical architecture, multi-agent orchestration design, and deployment strategy required to build this system within the strict 10-hour hackathon constraint. The proposed architecture leverages MongoDB Atlas as the core context and vector engine, Amazon Web Services (AWS) for scalable infrastructure, LangGraph for stateful agent orchestration, Voyage AI for adaptive retrieval, and LiveKit integrated with ElevenLabs for real-time, ultra-low-latency voice interactions.

## **The Prolonged Coordination Engine**

The process of managing an NHS waiting list and delegating appointments is inherently asynchronous and spans extensive timeframes. A patient may receive an SMS regarding a cancelled appointment, take several hours to review their personal schedule, and then reply. Alternatively, an outbound AI voice call might encounter an answering machine, requiring the system to leave a message and await an inbound callback or text response. Standard synchronous application architectures cannot handle these delays without consuming excessive compute resources or dropping active threads.

To satisfy the Prolonged Coordination theme, the architecture must abandon synchronous script execution and instead adopt a state-machine approach capable of enduring failures, restarts, and delayed responses. By utilizing LangGraph in conjunction with the MongoDB LangGraph Checkpointer, the system serializes the precise state of the AI agent's workflow directly into a MongoDB Atlas collection.7

LangGraph models agent workflows as directed graphs consisting of nodes (Python functions encoding agent logic) and edges (conditional transitions based on current state).6 When the system initiates an outbound communication, the active LangGraph node executes the network request and transitions into a suspended state. At this exact moment, the langgraph-checkpoint-mongodb library saves all contextual variables—including the patient's unique identifier, the specific clinical slot offered, the channel used, and a precise timestamp—into MongoDB Atlas.7

If the application crashes, or if hours pass before a webhook from a Twilio SMS reply triggers the system, the agent perfectly rehydrates its state from MongoDB Atlas and resumes reasoning from the exact node where it suspended.10 This implementation demonstrates an intricate, multi-step workflow that proves the agent's ability to retain reasoning state over long durations. Furthermore, the system handles single failures gracefully; if a communication API times out, the LangGraph execution catches the exception, logs the failure in the MongoDB document, and routes the graph execution via a conditional edge to an alternative communication node, such as dispatching an email instead of an SMS.

## **Multi-Agent Collaboration and the Contextual Whiteboard**

While Prolonged Coordination handles the temporal challenges of the waitlist, Multi-Agent Collaboration organizes the diverse skills required to execute the highly nuanced delegation process. The architecture will feature a specialized network of agents communicating through a shared context stored in MongoDB, essentially utilizing the database as a highly concurrent operational whiteboard.11

The system design necessitates a hierarchical orchestration pattern, moving away from single monolithic prompts toward specialized, independent actors.

| Agent Designation | Core Function and Specialization | Integration with MongoDB Atlas |
| :---- | :---- | :---- |
| **Supervisor Agent** | Acts as the central orchestrator. Monitors the clinical schedule for cancellations and delegates sub-tasks to specialized worker agents.6 | Reads schedule modifications from MongoDB Change Streams. Updates high-level appointment statuses in the Appointments collection.13 |
| **Queue Manager Agent** | Responsible for analyzing a newly available slot and generating a prioritized list of eligible patients based on clinical equity and urgency. | Executes complex vector searches against the Patients collection using Voyage AI embeddings to rank candidates.4 |
| **Outreach Orchestrator** | Determines the optimal communication channel (voice, SMS, email) for a specific patient based on historical preferences, language needs, and accessibility requirements. | Queries the AgentMemories collection to retrieve long-term contextual preferences previously learned about the patient.8 |
| **LiveKit Voice Agent** | Executes real-time WebRTC audio conversations. Handles interruptions, parses spoken intent, and provides human-like auditory feedback.16 | Logs communication transcripts into the MongoDB checkpointer. Triggers tool calls to update appointment states based on verbal confirmation.18 |
| **Messaging Agent** | Formats and dispatches asynchronous text-based communications via SMS or email APIs, ensuring phrasing matches patient comprehension levels. | Monitors incoming webhooks and updates the LangGraph state document in MongoDB to resume suspended coordination threads.6 |

By separating these concerns, the architecture proves how agents convey their specialized skills, identify suitable peers for sub-tasks, and share vast amounts of context without exceeding language model token limits. Rather than passing the entire history of the waitlist in a single context window, agents pass MongoDB document IDs, allowing downstream agents to retrieve only the specific data required for their designated task.19

## **Adaptive Retrieval with Voyage AI and Vector Search**

To implement the intelligent matching required to route the next patient in line based on severity and suitability, the system will leverage Voyage AI's state-of-the-art embedding models integrated natively with MongoDB Atlas Vector Search. When a highly specific slot becomes available—for example, a physiotherapy follow-up requiring bariatric equipment and wheelchair accessibility—static rules-based filtering often fails to capture the nuanced, unstructured needs documented in clinical notes.

The architecture will utilize the voyage-3-large or voyage-multimodal-3.5 embedding models to vectorize complex patient profiles during the data ingestion phase.4 These models transform unstructured text regarding the patient's symptoms, required mobility aids, and language preferences into dense, high-dimensional numerical vectors.15

When the Supervisor Agent detects a cancellation, the Queue Manager Agent executes an adaptive retrieval workflow. First, it transforms the characteristics of the cancelled slot into a query vector. It then performs a semantic cosine similarity search across the MongoDB Patients collection to identify a broad set of suitable candidates.15 To refine this list, the agent utilizes a dynamic chunking and re-ranking approach. It passes the top-K results through Voyage AI's rerank-2.5 model, instructing the reranker to prioritize patients based on a composite prompt weighting clinical urgency and geographic proximity.4

This represents true Adaptive Retrieval. If the top five patients reject the slot, the agent does not merely move down a static list; it dynamically alters its query approach. It may adjust the semantic search parameters to expand the geographic radius or lower the strictness of the specialty match, ensuring the system continually improves its search strategy over the duration of the multi-day workflow until the slot is successfully filled.23

## **Engineering the Transparent Delegation Process**

The core value proposition of the proposed pivot is the elimination of the "black box" of NHS appointment delegation. Patients and administrators must understand exactly why a decision was made, how the queue is ordered, and what options remain available. This transparency is achieved through a meticulous design of the LangGraph conditional edges and the explicit generation of human-readable audit logs within MongoDB.

The workflow begins when the Supervisor Agent detects a cancellation event via a simulated Electronic Patient Record (EPR) webhook.1 The execution flow follows a rigorous, stateful graph. Following the Adaptive Retrieval phase, the system generates a ranked list of the top eligible patients. The graph then enters a deterministic loop known as the Outreach Cycle. The Outreach Orchestrator Agent examines the first patient in the ranked list, queries the AgentMemories collection to determine the patient's preferred contact method, and delegates execution to either the Voice Agent or the Messaging Agent.8

Once the communication is dispatched, the LangGraph execution yields, committing its entire thread state to the MongoDB Checkpointer.6 The system establishes a configurable timeout. If the patient replies with an affirmative acceptance via SMS or verbally confirms during the AI phone call, a webhook triggers the graph to resume. The state machine transitions to the booking confirmation node, updating the MongoDB Appointments collection and halting the cycle.

### **Algorithmic Fairness and Handling Patient Rejections**

The true intelligence of the system, and its adherence to the user's requirement for empathetic care, is demonstrated when a patient declines the appointment or is unavailable. In a traditional system, a declining patient simply loses their chance and returns to the void of the waiting list. In this agentic system, the AI actively analyzes the schedule to provide immediate alternatives.

If the timeout expires without a response, or if the patient explicitly rejects the slot, the LangGraph resumes and transitions to an alternative opportunity node. The agent queries MongoDB for future available capacity that matches the patient's vector profile. It then generates a highly personalized, empathetic message via the preferred channel. The logic ensures the patient receives communication explicitly stating their status: "I understand tomorrow does not work for you. You remain in your current position on our priority waitlist. Based on current capacity, your next opportunity will likely be in approximately three weeks. Would you like me to note any specific days of the week to avoid for future short-notice offers?"

This interaction ensures the patient feels cared for and informed, achieving the goal of an honest and transparent process. If the patient responds with new constraints (e.g., "Please avoid Tuesday mornings"), the language model extracts this parameter and persistently saves it into the MongoDB AgentMemories collection using the langgraph-store-mongodb utility.8 Following this interaction, the graph loops back to the Outreach Cycle, seamlessly selecting the next patient in the vector-ranked list and initiating a new communication thread.

### **The Administrative Transparency Dashboard**

To secure high marks in the "Live Demo" and "Creativity" judging categories, the backend complexity must be made visually comprehensible to the judging panel. Because Streamlit is explicitly banned by the hackathon rules 1, the frontend will be constructed using Next.js.3 Next.js provides a robust React framework capable of delivering a highly polished, interactive administrative dashboard that visualizes the real-time state of the LangGraph multi-agent system.26

The Next.js application, hosted on AWS Amplify or Vercel, will utilize MongoDB Change Streams to push real-time updates to the web client via WebSockets.13 As the LangGraph system traverses its nodes, the dashboard will visually highlight the active agent. When the Voyage AI vector search is performed, the dashboard will display the top-ranked patients alongside an AI-generated natural language explanation of the ranking rationale. For example, the dashboard will display: "Patient 104 selected due to a 94% semantic match with bariatric equipment requirements and an elevated clinical urgency flag." This real-time visualization of the agent's internal reasoning completely demystifies the delegation process, proving to the judges that the system operates with absolute fairness and logic.

## **Implementing Ultra-Low-Latency AI Voice Outreach**

To maximize the chance of winning the "Best Use of ElevenLabs" bonus prize and to deliver a highly impactful live demonstration, the project must feature flawless, conversational voice interactions.27 The architecture will utilize the LiveKit Agents Python framework combined with ElevenLabs' text-to-speech (TTS) models to power the outbound voice caller.16

### **Telephony Architecture and SIP Trunking**

When the LangGraph state machine transitions to the voice communication node, a Python application hosted on AWS Elastic Container Service (ECS) initiates an outbound call.9 This requires a Session Initiation Protocol (SIP) trunk provider, such as Twilio, integrated with LiveKit's SIP infrastructure.18 The LangGraph node utilizes the LiveKit server SDK to dispatch a specialized outbound-caller agent to a newly created LiveKit room, simultaneously dialing the patient's phone number.30

The voice agent itself is constructed as a continuous streaming pipeline. When the patient answers, their audio is streamed via WebRTC to the LiveKit server and processed by a fast Speech-to-Text (STT) model.31 The transcribed text is fed into a fast Large Language Model (LLM)—such as Anthropic Claude 3 Haiku or OpenAI GPT-4o-mini hosted on Amazon Bedrock—which generates the conversational response.6 This text is immediately streamed to the ElevenLabs TTS engine.

### **Optimizing ElevenLabs Integration for Conversational Fluidity**

To achieve the conversational fluidity required for a sensitive healthcare application, the system will utilize the eleven\_turbo\_v2\_5 model via LiveKit Inference.5 LiveKit Inference runs the ElevenLabs models directly on LiveKit's infrastructure, significantly reducing network hops and minimizing the time-to-first-byte (TTFB) latency, ensuring the AI responds as quickly as a human operator.31

The voice agent will be primed with a strict system prompt and access to specific external functions, utilizing LangChain's tool-calling capabilities. The prompt will instruct the agent on its persona: a polite, highly efficient NHS scheduling assistant. The prompt will dynamically inject real-time context retrieved from MongoDB, ensuring the agent knows the patient's name, the specialty of the appointment, and the exact time of the offered slot.

### **Advanced Voice Capabilities and Clinical Safety Escalations**

The LiveKit framework provides native support for turn-taking, interruption handling, and voice activity detection (VAD).17 If the agent begins offering the appointment details and the patient interrupts to ask for clarification regarding the hospital location, the VAD system immediately halts the ElevenLabs audio playback, processes the interruption, and responds contextually based on the data retrieved from MongoDB.

Crucially, the voice agent must be equipped to handle medical edge cases safely to comply with the hackathon rule banning the generation of medical advice.1 The system architecture identifies "symptoms changed" as a critical risk factor. If the patient states, "I cannot make the appointment because my chest pain has gotten much worse," the LLM will recognize this semantic trigger. Through function calling, the voice agent will immediately execute an escalate\_to\_human tool.18

This tool execution achieves three critical actions simultaneously. First, it gracefully concludes the call by stating, "I understand your symptoms have changed. I am transferring your file to a clinical triage nurse who will review your case immediately." Second, it updates the MongoDB LangGraph checkpointer, routing the workflow out of the automated delegation cycle. Third, it places the patient into a high-priority, human-reviewed administrative queue displayed on the Next.js dashboard, ensuring the AI never attempts to diagnose or advise the patient independently. Additionally, the voice agent will implement logic to detect answering machines.18 If a voicemail greeting is detected, the agent pauses, waits for the tone, and utilizes ElevenLabs to leave a natural-sounding message outlining the available appointment and instructing the patient to reply via SMS to claim it.

The Agent Orchestrator implements the logic where a declined slot triggers the alternative opportunity generation. **04:00 PM – 05:00 PM: Polish, Edge Cases, and Rehearsal**

A strict code freeze on new features is enforced. The team focuses entirely on the live demo path. A deterministic, hard-coded "demo script" is created in the database to ensure the Voyage AI vector search always returns a specific, highly compelling synthetic patient as the top rank for the live presentation. The team practices the 3-minute pitch, ensuring the transition between viewing the Next.js dashboard and hearing the live ElevenLabs voice call over speakerphone is seamless.

To secure the first-place prize, the presentation and technical implementation must directly address the specific grading rubrics outlined by the judges: Impact Potential (20%), Live Demo (45%), and Creativity and Originality (35%).27

### **Impact Potential (20%)**

The narrative presented during the demo must emphasize that this system solves a massive, quantifiable healthcare crisis. The judges must understand that by transitioning from a reactive, manual calling process to a Prolonged Coordination agentic workflow, hospitals can recover thousands of hours of lost clinical capacity.1 Furthermore, the pivot to a transparent, fair delegation system directly addresses the ethical concerns surrounding AI in healthcare. By explicitly storing the reasoning for every queue movement in MongoDB and visually presenting it on the Next.js dashboard, the team demonstrates a commitment to algorithmic fairness. The architecture proves that AI can eliminate the administrative black box, providing patients with a highly personalized, caring interaction even when a specific appointment time does not work for them.

Given that the Live Demo holds the highest weight, technical reliability is paramount.27 The team must visually prove that the system is built entirely on MongoDB and AWS. The demo should commence with the Next.js dashboard showing an available slot. The presenter will trigger the slot release, and the dashboard will immediately display the Voyage AI vector search results, showing exactly why a specific synthetic patient was selected based on complex semantic matching.15

The climax of the demo will be the live outbound phone call. The LiveKit agent will dial a team member's actual phone on speaker. The team member will converse with the ElevenLabs-powered voice, demonstrating its low latency and natural tone.16 To prove the dynamic intelligence of the system, the team member will deliberately decline the appointment. The audience will hear the AI instantly calculate a future alternative based on MongoDB schedule data and update the patient's preferences in real-time. The dashboard will instantly reflect this interaction, showing the graph state resume, mark the patient as processed, and immediately trigger a simulated SMS to the next patient in line. Most hackathon submissions building AI agents focus on simple chat interfaces or highly isolated query tasks. This project differentiates itself by orchestrating a massive, asynchronous operational workflow. The originality lies in the synthesis of technologies: utilizing MongoDB not just as a database, but as a persistent memory store (Checkpointer and Store) that allows the LangGraph state machine to pause for hours and resume perfectly.7 Furthermore, the use of Voyage AI for adaptive retrieval of patient suitability—rather than simple RAG document lookup—showcases a deep understanding of vector mathematics applied to operational logistics. Coupling this with the LiveKit and ElevenLabs voice infrastructure elevates the project from a standard software utility to an autonomous, human-like administrative partner.

## **Risk Mitigation and Technical Fallbacks**

Live hackathon demonstrations involving external telecommunication APIs and language model inference are inherently prone to latency spikes and network failures. To guarantee a flawless presentation, several technical fallbacks must be engineered into the architecture.

| Risk Category | Potential Failure Mode | Engineered Mitigation Strategy |
| :---- | :---- | :---- |
| **Telephony Infrastructure** | The Twilio SIP trunk or LiveKit Cloud routing experiences severe latency or an outage during the live presentation on stage. | The LangGraph system is designed with an automatic fallback edge. If the Dispatch\_Voice\_Agent node times out or throws a connection exception, the graph gracefully catches the error and seamlessly routes to the Dispatch\_SMS\_Agent node, ensuring the delegation cascade continues without a fatal system crash.6 |
| **LLM Hallucination** | The AI voice agent dispenses medical advice or hallucinates non-existent appointment slots, violating hackathon rules and clinical safety parameters.1 | The system prompt is aggressively constrained and temperature is lowered. All slot data provided to the agent is strictly structured using JSON schemas. The LangGraph output parser validates that any tool call executed by the voice agent (such as confirm\_booking) contains a valid slot ID currently marked as available in MongoDB before executing the database write. |
| **Demo State Corruption** | During rigorous testing prior to the judging round, the MongoDB collections become polluted with half-finished LangGraph checkpoints or altered synthetic patient data. | The Next.js dashboard includes a highly visible "Reset Demo State" button that triggers an AWS Lambda function. This function drops the collections, re-seeds the pristine synthetic CSV data, and clears the LangGraph checkpoint namespaces, ensuring a perfect environment for the judges. |

The decision to pivot from a static rules-based engine to an agentic, transparent appointment delegation system is the definitive strategy required to excel at the MongoDB Agentic Evolution Hackathon. By fully embracing the Prolonged Coordination, Multi-Agent Collaboration, and Adaptive Retrieval themes, the project transcends simple chat applications, demonstrating a complex, stateful architecture capable of handling long-running asynchronous healthcare workflows. The technical blueprint provided—anchored by AWS infrastructure, MongoDB Atlas for persistent state and vector search, LangGraph for rigorous orchestration, and LiveKit/ElevenLabs for real-time voice interactions—provides a comprehensive roadmap for the 10-hour build. This architecture not only eliminates the administrative black box of NHS scheduling but also ensures a highly compelling, visually impressive, and flawlessly reliable live demonstration.
